pr-review — claude bez ustawień projektu, recenzja tylko PR-ów właściciela i botów

Data: 2026-11-15 · Gałąź: sprint/pr-review-hooks → dev · Źródło: audyt bezpieczeństwa home-ops 2026-11-15, znalezisko S1

1. Co zostało zrobione

Recenzent pr-review na uwh uruchamia claude -p w checkoutcie gałęzi PR-a. Bez dodatkowej flagi CLI wczytuje .claude/settings.json z tej gałęzi, a w trybie -p nie pyta o zaufanie. Hook z obcego PR-a wykonałby się więc na uwh, z dostępem do tokenu gh, klucza SSH i dockera. Zmiany:

  • pr_review_llm.call: do polecenia doszło --setting-sources user (zaraz po --strict-mcp-config). Wczytywane są tylko ustawienia użytkownika z uwh. settings.json i settings.local.json z repo są pomijane.
  • Nowy moduł ops/elitedesk/pr_review_filter.py: stała ALLOWED_AUTHORS (domyślnie PR_OWNER, dependabot[bot], app/dependabot, nadpisywana zmienną PR_REVIEW_AUTHORS). PR przechodzi tylko wtedy, gdy autor jest na liście, isCrossRepository == false i headRepositoryOwner to właściciel. Brak informacji o forku liczy się jako fork.
  • pr_decide.candidates() odrzuca takie PR-y przed pytaniem. Autora bierze z gh search prs, a pola forka z gh pr view --json isCrossRepository,author,headRepositoryOwner. Taki PR nie dostaje pytania, więc nie da się go „Scal”.
  • pr_review.pick() sprawdza to samo jeszcze raz na danych z view() przed checkout. Log: pominięty (fork): repo#n login albo pominięty (autor): repo#n login.
  • README (ops/elitedesk/README.md, sekcja PR review): akapit o filtrze i fladze. check.yml: nowy moduł na liście py_compile.

3. Scenariusz ręczny A: hook z repo PR-a się nie wykonuje

Wykonane na Macu 2026-11-15 (claude CLI z tą samą flagą co na uwh, model haiku, budżet 0,05 USD):

D=$(mktemp -d /tmp/sprint-hook-test.XXXX); mkdir -p $D/.claude
cat > $D/.claude/settings.json <<'EOF'
{"hooks":{"SessionStart":[{"hooks":[{"type":"command","command":"touch /tmp/sprint-hook-fired"}]}],
"UserPromptSubmit":[{"hooks":[{"type":"command","command":"touch /tmp/sprint-hook-fired"}]}]}}
EOF
rm -f /tmp/sprint-hook-fired; cd $D
claude -p --model haiku --setting-sources user --max-budget-usd 0.05 --no-session-persistence 'odpowiedz: ok' < /dev/null
test -e /tmp/sprint-hook-fired && echo TAK || echo NIE      # → NIE
claude -p --model haiku --max-budget-usd 0.05 --no-session-persistence 'odpowiedz: ok' < /dev/null
test -e /tmp/sprint-hook-fired && echo TAK || echo NIE      # → TAK (kontrola: bez flagi hook działa)
cd /tmp && rm -rf "$D" /tmp/sprint-hook-fired
WariantOdpowiedźPlik /tmp/sprint-hook-fired
z --setting-sources user„Ok.”nie powstał
bez flagi (kontrola)„ok”powstał: tak działał recenzent przed poprawką
