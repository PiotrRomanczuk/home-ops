1. What was actually done

This is the first step toward using home-ops as a hub for every project, not just one. Previously, the vault-sync agent (planner-sync.py) already discovered every project's Obsidian file and synced its Now/Next/Later into Postgres — but two pieces were still hardcoded to a single project (home-ops), and one real bug meant duplicate project files could silently overwrite each other with no warning. Four changes fix that:

ChangeBehavior nowFiles
Slug-collision guard If two vault files declare the same project: slug, the sync worker keeps the first one (deterministic, alphabetical) and logs a clear warn event instead of one silently clobbering the other with zero trace. agents/elitedesk/planner-sync.py
Multi-slug Board sync The Board tab's DB↔vault reconciliation loop (board_sync_once) used to run for exactly one project (BOARD_SLUG env var). It now reconciles every slug that has at least one board_tasks row, discovered via a new GET /api/board/slugs route, with per-slug watermark/hash state (backward-compatible with the old single-project state file). agents/elitedesk/planner-sync.py, ingest/src/routes/board.ts
Projects tab shows deployed/health/stack The vault's deployed, health, and stack frontmatter fields were already syncing into Postgres (raw_frontmatter jsonb) and already being fetched into the browser — but nothing ever rendered them. Now the grid card, compact list row, and drill page all show them (e.g. a small "🟢 strummy.vercel.app" line, and a stack summary on the drill page). ingest/public/projects.js, projects.css
Board tab slug switcher The Board tab was hardcoded to always show the home-ops board. It now has a dropdown (populated from known project slugs) and reads/writes the slug via the URL fragment (#tab=board&board_slug=job-search), so any project's board can be opened and used independently. ingest/public/board.js, board-api.js, board.css

Not part of this change (separate vault-only work, no code): archived 2 stale duplicate project files and added 3 missing project stubs so all 15 CLAUDE.md-listed projects have a vault entry. One duplicate (home-ops) is still unresolved pending a decision on how to merge its content — see the conversation, not this report.

2. Test setup — local, disposable stack

Important: all commands below target a local Postgres/ingest stack started via docker compose in this repo, never elitedesk/production. Test 1's seed step calls POST /api/projects/sync, which deletes any project slug not in the payload — fine against an empty local dev database, destructive against the real one.
# from the repo root
./scripts/generate-env.sh        # bootstraps .env (POSTGRES_PASSWORD, INGEST_TOKEN, prompts LOGS_PASSWORD)
docker compose up -d --build     # postgres (fresh volume auto-applies postgres/migrations/*.sql) + ingest on :64421

curl -s http://127.0.0.1:64421/api/health   # expect {"ok":true,...}

export INGEST_TOKEN=$(grep '^INGEST_TOKEN=' .env | cut -d= -f2)

3. Test 1 — slug-collision guard

Simulates two vault files (e.g. projects/home-ops.md and projects/Private/home-ops.md) both declaring project: dup-test.

mkdir -p /tmp/hub-test-vault/.git /tmp/hub-test-vault/projects/Private

cat > /tmp/hub-test-vault/projects/dup-test.md <<'EOF'
---
project: dup-test
status: hot
---
# dup-test (top-level copy)
## Now
- [ ] top-level task
EOF

cat > /tmp/hub-test-vault/projects/Private/dup-test.md <<'EOF'
---
project: dup-test
status: warm
---
# dup-test (Private copy — should be ignored)
## Now
- [ ] private task
EOF

cd agents/elitedesk
PLANNER_DIR=/tmp/hub-test-vault \
INGEST_URL=http://127.0.0.1:64421/api/ingest \
INGEST_TOKEN=$INGEST_TOKEN \
SYNC_INTERVAL=999999 \
timeout 5 python3 planner-sync.py || true
cd -

Then check the warning landed in host_logs:

curl -s "http://127.0.0.1:64421/api/logs?grep=duplicate+project+slug&since_min=5" \
  -H "X-Ingest-Token: $INGEST_TOKEN" | python3 -m json.tool

curl -s "http://127.0.0.1:64421/api/projects/dup-test" \
  -H "X-Ingest-Token: $INGEST_TOKEN" | python3 -m json.tool
Expected: the logs response contains one warn event whose message starts with duplicate project slug "dup-test" and whose data.kept/data.ignored point at dup-test.md and Private/dup-test.md respectively. The synced project row's status is hot (from the kept top-level file) — not warm.

4. Test 2 — Projects tab surfaces deployed/health/stack

Seed two fake projects directly (skips planner-sync entirely — exercises the same /api/projects/sync endpoint the agent uses):

curl -s -X POST http://127.0.0.1:64421/api/projects/sync \
  -H "X-Ingest-Token: $INGEST_TOKEN" -H "Content-Type: application/json" \
  -d '{"projects":[
    {"slug":"demo-app","title":"Demo App","status":"hot","commits_30d":12,
     "now_md":"- [ ] ship the thing","next_md":"- [ ] polish",
     "raw_frontmatter":{"deployed":"demo-app.vercel.app","health":"🟢",
       "stack":"Next.js · Tailwind · Postgres"}},
    {"slug":"quiet-app","title":"Quiet App","status":"dormant","commits_30d":0,
     "now_md":"","next_md":""}
  ]}'

Open http://127.0.0.1:64421/#tab=projects in a browser (log in with the LOGS_PASSWORD you set, unless AUTH_PUBLIC=1).

Expected:
  • demo-app's grid card shows a small line under the title with 🟢 and demo-app.vercel.app.
  • quiet-app's card shows no such line (no deployed/health in its frontmatter) — confirms the new code doesn't render an empty row.
  • Switch to list view (☰ list) — demo-app's slug is prefixed with 🟢, quiet-app's isn't.
  • Click into demo-app's drill page — the header shows the health emoji next to the title, the meta row has a clickable ⇗ demo-app.vercel.app link (opens https://demo-app.vercel.app in a new tab), and a "stack" line reads Next.js · Tailwind · Postgres.

5. Test 3 — Board tab slug switcher

With the two projects from Test 2 still seeded, open http://127.0.0.1:64421/#tab=board.

Expected:
  • A dropdown appears next to the "board" label in the section bar, listing demo-app, quiet-app (and home-ops — always included even with zero cards, per the "always reconciled" default).
  • Default view (no board_slug in the URL) shows the home-ops board.
  • Select demo-app — the URL becomes #tab=board&board_slug=demo-app, the board clears (empty columns, "drop here" placeholders — no demo-app cards exist yet).
  • Click + under "Now" and add a card, e.g. "test card A". Switch to quiet-app via the dropdown — the board is empty again (no bleed from demo-app). Switch back to demo-app — "test card A" is still there.
  • Reload the page with #tab=board&board_slug=demo-app directly in the address bar — it lands straight on demo-app's board (state survives a hard refresh, not just client-side navigation).

Confirms the DB-authoritative board actually writes back into the right project's markdown file when more than one project has cards — the part Test 3 can't show on its own since it doesn't involve planner-sync. Needs a real (or fake, git-initialized) local vault clone.

Expected: after adding a Board-tab card for dup-test (repeat the Test 3 steps with board_slug=dup-test) and re-running the snippet above, projects/dup-test.md's ## Now section is rewritten to include the new card, and git log shows a new board sync: dup-test commit — not a home-ops commit, and home-ops's own board/vault file is untouched by this tick.

7. Edge cases worth checking

  • Bare vs. schemed deployed URL: try raw_frontmatter.deployed as both "foo.vercel.app" (bare domain, as most vault files use) and "https://foo.vercel.app" — both should produce a working link on the drill page (the code prefixes https:// only when no scheme is present).
  • Redeploy after this change: an existing <PLANNER_DIR>.state.json from before this change is a flat {"watermark":...,"hash":...}. Confirm _load_state() adopts it as the BOARD_SLUG project's state (not lost, not misapplied to a different slug) — covered by agents/tests/test_planner_sync.py::TestLoadState, but worth re-confirming against a real old state file from elitedesk before deploying.
  • /api/board/slugs unreachable: stop the ingest container mid-tick and confirm planner-sync logs a warn (not a crash) and falls back to reconciling just BOARD_SLUG.
  • Empty stack/health/deployed: a project with none of the three should render identically to before this change (no stray empty elements/whitespace on the card or drill page).
