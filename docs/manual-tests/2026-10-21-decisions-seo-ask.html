Decisions: tygodniowy PR SEO pyta przed scaleniem; ukryte martwe karty

Date: 2026-10-21 · branch feat/decisions-seo-ask

Co zrobiono

  • ops/elitedesk/seo_decide.py: dla każdego otwartego PR z etykietą seo-auto w gitara-lekcje zakłada pytanie w Decisions („Scalić PR SEO #N?”, Scal / Odrzuć, ważne 7 dni). Odpowiedź Scal → gh pr merge --squash --delete-branch; Odrzuć → zamknięcie PR z powodem w komentarzu, hipotezy z in_pr wracają do proposed. Nieudany merge zostaje niezużyty i wraca w następnym przebiegu.
  • Uruchamiane na początku i końcu seo-improve.sh oraz 2× dziennie (seo-decide.timer, 08:15 i 19:15), więc „tak” ląduje w ciągu ~12 h, nie w następny poniedziałek.
  • Konsola: Chat, Evals, Scores ukryte (dalej dostępne klawiszem 3/7/9 i przez #tab=). Decisions widać tylko, gdy jest otwarte pytanie (albo gdy karta jest aktywna).

Weryfikacja (wykonana)

  1. Branch wdrożony na uwh, seo_decide.py uruchomiony ręcznie: „asked about PR #9”; drugi przebieg: „asked 0” (bez duplikatu).
  2. Pasek kart: Dziś, Status, Projects, Logs, Hosts, Board, Decisions 1.
  3. Karta Decisions pokazuje pytanie o PR #9 z linkiem do PR i przyciskami.
  4. Testy: ops/elitedesk/tests/test_seo_decide.py (6: merge, close+powód, retry po błędzie, brak ref, pytanie raz na PR, bez duplikatów).

Jak przetestować ręcznie

  1. Otwórz http://home-ops.local/#tab=decisions, kliknij Scal przy PR #9.
  2. Na uwh: systemctl --user start seo-decide.service; journalctl --user -u seo-decide -n 5 → „PR #9 merged”. Na GitHubie PR #9 scalony, gałąź usunięta.
  3. Karta Decisions znika z paska (brak otwartych pytań).
  4. Odrzucenie: wpisz powód, Odrzuć → po przebiegu PR zamknięty z komentarzem „Odrzucone w home-ops Decisions: …”, w seo_plan wiersze tego PR mają status proposed.
  5. Edge: PR z konfliktem → log „gh failed … will retry next run”, decyzja dalej niezużyta.
