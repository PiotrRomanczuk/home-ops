  • Opt-in we frontmatterze: notatka z zadania: github i repo: (właściciel z GITHUB_OWNER, domyślnie PiotrRomanczuk). Inne notatki bez zmian.
  • agents/elitedesk/issues_md.py (czyste funkcje): linia w formacie rubryki §8 — - [ ] 💰 L ⛓ 🖥 2026-11-12 **Tytuł** — [#1028](url); klasa z klasa/*, rozmiar z size-*, data z ukrytego <!-- planner-date: … --> w treści issue (inaczej data utworzenia). Sortowanie: klasa → ⛓ → rozmiar → numer. Link na końcu po „ — ”, więc taskTitle na „Dziś” pokazuje sam tytuł.
  • Blok generowany między <!-- github-issues:start … --> a <!-- github-issues:end --> w każdej sekcji. Linie poza blokiem (zadania poufne — repo jest publiczne) nie są ruszane. Brak bloku → wstawiany pod nagłówkiem; brak sekcji → pomijana.

  • Odhaczenie na „Dziś”: linia z bloku → zamknięcie issue w GitHubie (markdown nietknięty, następny tick renderuje bez czekania 5 min). Ręczna linia — nawet z linkiem do issue — dalej przełącza checkbox w markdownie.

Jak przetestować ręcznie

  1. Render bez hosta (Mac, na kopii notatki):
    cp ~/Obsidian/MainCV-Planner/1-Projekty/Strummy/Strummy.md /tmp/s.md
python3 -c "
import sys; sys.path.insert(0,'agents/elitedesk')
from pathlib import Path
from issues_gh import fetch_open_issues
from issues_md import render_issue_blocks, replace_issue_blocks
p=Path('/tmp/s.md'); t=p.read_text()
n=replace_issue_blocks(t, render_issue_blocks(fetch_open_issues('PiotrRomanczuk/strummy')))
print('bez zmian' if n==t else 'zmienione bloki')"
    Oczekiwane: bez zmian, dopóki nikt nie ruszył issues; po zmianie etykiety plan/* jednego issue — zmienione bloki.
  2. Deploy na uwh (po merge, z czystego dev/main): 
    scripts/deploy-agent.sh elitedesk planner-sync   # dochodzą issues_md.py i issues_gh.py
    W logach planner-sync (źródło agent:planner-sync) brak issues fetch failed; przy pierwszej zmianie issues linia issues sync: strummy i commit w repo vaulta.
  3. Etykieta: w issue #1050 zmienić plan/later → plan/next. W ciągu ~5 min commit issues sync: strummy, linia przenosi się z Later do Next w notatce i na „Dziś”. Cofnąć etykietę.
  4. Zamknięcie przez PR: PR z Closes #n po scaleniu → linia znika z bloku przy następnym ticku.
  5. Odhaczenie na „Dziś”: kliknąć checkbox przy linii z bloku → issue zamknięte w GitHubie, linia znika po kilku sekundach–minucie. Kliknąć ręczną linię 🔴 (np. „Bramki przed pierwszym zaproszeniem ucznia”, ma link do #1034) → przełącza się tylko checkbox w notatce, #1034 zostaje otwarte.
  6. Brzegi: ręczna edycja wewnątrz bloku w Obsidianie → nadpisana przy następnym renderze (zamierzone); usunięcie znaczników → blok wraca pod nagłówkiem; brak sieci do GitHuba → issues fetch failed w logach, notatka nietknięta.
