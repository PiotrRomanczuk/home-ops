Data: 2026-10-20 · Gałąź: feat/queue-card · ADR: docs/adr/2026-10-20-queue-state.md · Projekt UI: Claude Design „home-ops · Kolejka agentów”, opcja 1a

Co zostało zrobione

Vault ma od 2026-10-19 plik QUEUE.md (okno pracy, jeden bilet w toku, kolejka wg rubryki, tor lokalny, „Czeka na Piotra”, „Zrobione”). Do tej pory home-ops go nie znał. Teraz:

  • planner-sync parsuje QUEUE.md co tick nowym modułem agents/elitedesk/queue_md.py i wysyła wynik na POST /api/queue/sync tylko, gdy plik się zmienił (md5). Brak pliku = cicho nic.
  • Migracja 023 tworzy jednowierszową tabelę queue_state (nagłówek okna + sections/summary jako jsonb + source_hash). API też pomija zapis przy tym samym hashu.
  • GET /api/queue zwraca wiersz; GET /api/today niesie go jako pole queue.
  • Karta „Kolejka” (today-queue.js, style w today.css) na górze prawej kolumny „Dziś”: okno i fokus, pasek pojemności (godziny z „Zrobione” vs pojemność, plus budżet biletu w toku wg rozmiaru S=1 h, M=3 h, L=8 h), bilet w toku, następne 3 z kolejki, linia liczników. Klasy rubryki jako chipy tekstowe (ryzyko / przychód / fokus / higiena / pomysł), nie emoji.
  • deploy-agent.sh wysyła na hosta także moduły pomocnicze agents/<host>/*_*.py (bez tego queue_md.py nie trafiłby do ~/bin).
  • CI: migracja 023 w zestawie testów integracyjnych + queue.test.ts.

Zrzut: karta na realnych danych z QUEUE.md (2026-10-20)

A — stan rzeczywisty (W toku puste → karta pokazuje „następny bilet z kolejki”). B — ten sam plik z biletem przeniesionym do „W toku” (podświetlony wiersz, budżet w pasku). Render przez statyczny harness z oryginalnym h() i arkuszami konsoli.

Jak przetestować ręcznie

  1. Parser na prawdziwym pliku (Mac, bez hosta):
    cd home-ops && python3 -c "
import importlib.util,json,pathlib
s=importlib.util.spec_from_file_location('q','agents/elitedesk/queue_md.py');m=importlib.util.module_from_spec(s);s.loader.exec_module(m)
print(json.dumps(m.parse_queue_md(pathlib.Path.home().joinpath('Obsidian/MainCV-Planner/QUEUE.md').read_text())['summary'],ensure_ascii=False))"
    Oczekiwane: liczniki sekcji i done_hours zgodne z plikiem.
  2. Deploy na uwh (po merge, z czystego main): 
    git pull
scripts/apply-migrations.sh                     # 023_queue_state
docker compose up -d --build ingest
scripts/deploy-agent.sh elitedesk planner-sync   # rsync planner-sync.py + queue_md.py
  3. Sync: w logach planner-sync (Logs, źródło agent:planner-sync) w ciągu 60 s linia queue sync ok z licznikami. curl -s -H "X-Ingest-Token: …" http://192.168.1.75:64421/api/queue | jq .queue.summary.
  4. Karta: otworzyć konsolę, zakładka „Dziś” (klawisz 1). Prawa kolumna zaczyna się od „Kolejka”: okno 19.10 → 25.10, pasek, bilety. Zmienić coś w QUEUE.md w Obsidianie (np. przenieść bilet do „W toku”) → po ≤ 60 s sync + ≤ 60 s odświeżenie karty wiersz jest podświetlony i pasek pokazuje budżet.
  5. Brzegi: usunąć QUEUE.md z lustra → karta znika, brak błędów; linia bez klasy/rozmiaru → pokazana jako zwykły tekst; POST /api/queue/sync bez tokena → 401; ponowny POST z tym samym source_hash → {"status":"unchanged"}.
