Gmail → Postgres: schemat gmail + rutyna gmail-daily

Date: 2026-10-26 · branch feat/gmail-cleanup · ADR docs/adr/2026-10-26-gmail-postgres.md

Co zostało zrobione

  • Migracja 025_gmail.sql: schemat gmail z tabelami message (nagłówki, klucz = REST id), rule + config (reguły kategoryzacji jako wiersze), applied (każda linia dziennika undo → jeden wiersz na wiadomość), message_state (aktualna kategoria/podkategoria/flagi), funkcja gmail.rules_json() (reguły w kształcie JSON, który klasyfikator już czyta) i widok gmail.category_summary. Idempotentna.
  • gmail_db.py: transport docker exec psql jak w seo_db.py; ładowanie masowe przez COPY FROM STDIN do tabeli tymczasowej + upsert. Czyste helpery (message_row, journal_rows, copy_block) mają testy.
  • gmail_import.py: jednorazowy backfill messages | journals | rules | state | all ze stanu z Maca.
  • gmail_classify.rules_from_dict(): jeden parser dla pliku JSON i dla gmail.rules_json(); GMAIL_RULES=db wybiera Postgres. Nowa flaga automated_only (reguła tematu tylko dla nadawców botowych) i szerszy regex nadawców automatycznych.
  • gmail-daily.py + unit/timer 06:40: inwentarz nowych maili przez IMAP → klasyfikacja → reconcile etykiet kategorii (nigdy Kosz) → message_state → karta w digestcie.
  • README (sekcja „Gmail routine”), ADR, CI py_compile dla nowych plików, .gitignore dla gmail-daily.env.
