Rejestr miejsc (storage_places) — lustro notatek vaulta w Postgresie

Data: 2026-11-12 · Gałąź: feat/storage-places · ADR: docs/adr/2026-11-12-storage-places.md · Plan w vaulcie: 3-Zasoby/analysis/2026-11-12-porzadek-wszystkich-miejsc.md

Co zostało zrobione

Rejestr miejsc z danymi (STORAGE.md) był jedną tabelą markdown. Od dziś każde miejsce to osobna notatka w 2-Obszary/mapy/miejsca/ z polami we frontmatterze (78 notatek). Ta zmiana dokłada lustro w Postgresie, tak jak dla notatek projektów:

  • Migracja 034 — tabela storage_places (klucz id = numer miejsca), statusy jako CHECK: porzadek ok / do-poprawy / problem / niesprawdzone, backup to samo + nie-wymaga / brak-oceny, stan aktywne / usuniete; daty sprawdzone i test_odtworzenia; sprawdzenie = polecenie do audytu.
  • agents/elitedesk/storage_md.py — parser notatek (tylko type: miejsce), wartości przechodzą bez zgadywania.
  • planner-sync — nowy krok storage_sync_once(): wysyła komplet na POST /api/storage/sync tylko gdy notatki się zmieniły (md5); odrzucone notatki loguje ze ścieżką.
  • POST /api/storage/sync (token) — walidacja w storage-model.ts, upsert po id, usunięcie id, których nie ma już w vaulcie, w jednej transakcji; pusty zestaw → 400, żeby zepsuty klon nie wyczyścił tabeli.
  • GET /api/storage (podgląd lub token) — miejsca wg id, filtry stan, porzadek, backup, gdzie, liczniki statusów.
  • CI: migracja 034 w zestawie integracyjnym + storage.test.ts.

Poprawki r2 (2026-11-16)

Recenzja r11: częściowy odczyt vaulta nadal kasował wiersze. Poprawione:

  • parse_places — plik NN-*.md, którego nie da się odczytać (bajt spoza UTF-8), bez frontmattera albo z type ≠ miejsce (np. Miejsce), trafia do payloadu jako zaślepka {id: NN, nazwa: null, unparsed: "…"}. Serwer odrzuca ją (nazwa required, z id), więc wiersz zostaje, a planner-sync loguje notatkę w rejected. Pliki bez prefiksu NN- (README, szablon) są pomijane.
  • id: "4" (string cyfr) → 4; brak id → numer z prefiksu nazwy pliku.
  • Frontmatter zamknięty --- na końcu pliku bez \n jest rozpoznawany.
  • Testy: 7 nowych w ParsePlacesTest (bajt \xff, frontmatter bez końcowego \n, type: Miejsce, brak frontmattera, id: "4", brak id, pominięty README) + storage.test.ts: sync [1, 2] → [1, zaślepka 2] daje removed: 0, wiersz 2 bez zmian.

Ręcznie: w kopii vaulta zepsuć jedną notatkę (dopisać bajt \xff, zmienić type: Miejsce, usunąć frontmatter), uruchomić planner-sync → w logu rejected ze ścieżką, removed: 0, miejsce nadal w GET /api/storage.

Bramki: agents/tests 104 OK; npm run check zielone; vitest z Postgresem 17 (migracje jak w check.yml + 017, 034 dwa razy) 149/149, storage.test.ts 6/6.

Poprawki r3 (2026-11-17)

Recenzja r13: zły id w notatce nadal kasował wiersz. Poprawione:

  • Numer z nazwy pliku jest id. Notatka NN-*.md z type: miejsce, której id się nie zgadza (8a, 0, > 9999, cudzy numer), daje zaślepkę {id: NN, nazwa: null, unparsed: "id … ≠ file number NN"}. Wiersz NN zostaje, cudzy wiersz nie jest nadpisywany, notatka trafia do rejected.
  • Notatka type: miejsce przemianowana bez prefiksu NN- (z poprawnym id ≥ 1) daje zaślepkę z jej id. README* i inne pliki bez type: miejsce są pomijane.
  • storage_md.py dopisany do py_compile w check.yml; ADR uzupełniony.
  • Testy (ParsePlacesTest, +5): id: 8a, id: 0, 09-x z id: 10 obok 10-y (zaślepka 9 + pełny rekord 10 z 10-y.md), jedenascie.md z id: 11, bezprefiksowa nie-miejsce pominięta.
  • Punkt 5 (merge origin/dev po #85): pominięty, #85 w chwili poprawki nie był scalony.

Ręcznie: w kopii vaulta zmienić id w 08-*.md na 8a albo skopiować notatkę pod 09-… bez zmiany id, uruchomić planner-sync: w logu rejected ze ścieżką, removed: 0, wiersze 8 i 9 nadal w GET /api/storage.

Bramki: agents/tests 109 OK; ops/elitedesk/tests 93 OK; py_compile OK; npm run check zielone; vitest z Postgresem 17 (migracje jak w check.yml + 017) 149/149.
