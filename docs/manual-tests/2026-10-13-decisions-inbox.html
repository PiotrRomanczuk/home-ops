Decisions inbox + digest rewrite

Date: 2026-10-13 · Branch: feat/decisions-inbox · Verified against a local copy of live elitedesk data (30 days of errors, probes, projects, board)

What was built

  • The morning email is now a report from the routines, not a server dashboard. It opens with one verdict sentence (also the subject line), then only the sections that have content: decisions waiting for you, recurring problems, hosts, sites, today's focus, routine cards.
  • Routines report through one contract. Each run posts a card: one headline, up to five items, one metric with a delta. A card older than 26 hours shows as "did not run" instead of pretending to be today's news.
  • Routines ask before anything public. A routine files a decision and stops. The email shows one-tap buttons. Opening a button shows a confirmation page; only confirming records the answer, so mail-client link prefetching can never answer for you. Saying no asks for a one-line reason.
  • The console has a Decisions tab (key 9) with the same inbox, and a badge with the open count.
  • Errors are grouped into problems. One row per source and host, with how many times in 24 hours and since when. On live data: 2 961 rows became 5 problems, plus win10's 97% disk.
  • The evening run no longer queues a GPU job. That step added one job a day to a queue nobody runs since July: 98 jobs were stuck.

How to test it manually

Setup on elitedesk (after merge)

cd ~/code/logs-stack && git checkout main && git pull
scripts/apply-migrations.sh                       # applies 019 + 020
echo 'PUBLIC_BASE_URL=http://192.168.1.75:64421' >> .env
docker compose up -d --build ingest
curl -s localhost:64421/api/health                # {"ok":true}

1. Routine contract from the CLI

set -a; . ~/.config/elitedesk-watcher.env; set +a
python3 -m agents.routine_report card seo-analyse "Crawl findings down to 17" \
  --status warn --metric "crawl findings=17" --delta -2 --lower-is-better
python3 -m agents.routine_report ask seo-improve "Merge SEO PR #53?" --ref 53 --option yes:Merge --option no:Skip
python3 -m agents.routine_report ask seo-improve "Merge SEO PR #53?" --ref 53 --skip-if-open   # → skipped

Expected: the card JSON with an id, a decision with links.yes and links.no, then {"skipped": true}.

2. The email

ops/elitedesk/daily-digest.sh --dry-run > /tmp/d.html     # open in a browser
systemctl --user start daily-digest.service                # real send

Expected: subject starts with the verdict. "Needs you" lists the decision with Merge / Skip buttons. The seo-analyse card shows -2 in green.

3. Answer from the phone

  1. Tap Skip in the email. A confirmation page opens; nothing is recorded yet.
  2. Submit with an empty reason: the browser blocks it. Type a reason and confirm: "Recorded: Skip" with the reason.
  3. Tap the same button again: "This decision is answered."
  4. Change one letter of the signature in the URL: "Nothing recorded. This link is not valid." (403).

4. The routine picks it up

python3 -m agents.routine_report answers seo-improve        # shows answer + reason
python3 -m agents.routine_report consume seo-improve <id>
python3 -m agents.routine_report answers seo-improve        # → []

5. Console

Open http://192.168.1.75:64421/#tab=decisions (or press 9). Answer "yes" on an open decision; it moves to "answered", shows "via console". Deadlines read "expires in 1d", not "expires now".

Edge cases worth a look

  • A digest.d/*.txt file older than 26 hours is not rendered (touch -d '2 days ago' one and dry-run).
  • A decision past its expires_at disappears from "Needs you" and shows under "expired" in the console.
  • Hosts that send logs but no metrics (elitedesk, piotr-HP-EliteDesk, uwh today) collapse into one line.
